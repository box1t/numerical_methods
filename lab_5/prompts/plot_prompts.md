
## 📝 Техническое Задание (ТЗ) на Модуль Визуализации Численных Схем

### 1. 🎯 Цель

Разработать (или модифицировать существующий) Python-модуль, который выполняет комплексную визуализацию результатов численного моделирования дифференциальных уравнений в частных производных (ДУЧП) для сравнения различных численных схем (например, Явная, Неявная, Кранка-Николсона).

### 2. 🧱 Структура Модуля и Связанность

Модуль должен быть разбит на логические блоки с высокой связанностью (High Cohesion) внутри блоков и низкой зависимостью (Low Coupling) между ними, как показано в структуре функций.

#### 2.1. Блок Загрузки Данных (Data Loader)

| Функция | Описание | Вход | Выход |
| :--- | :--- | :--- | :--- |
| **`load_solution_data`** | Загружает пространственно-временные данные решения $(x, u_{\text{solved}}, u_{\text{true}})$ из файлов `*.txt`. | `path` (str): Путь к папке схемы. | `dict`: `{t: (x, u_solved, u_true)}` |
| **`load_error_data`** | Загружает временную зависимость погрешности (нормы) из файла `p.txt`. | `path` (str) | `tuple`: `(t_pogr, pogr_vals)` |
| **`load_all_data`** | Координатор загрузки всех данных для всех схем. | `paths_dict` (dict): `{'Name': 'Path'}` | `tuple`: `(all_data, all_pogr, all_times)` |

#### 2.2. Блок Визуализации (Plotting Engine)

| Функция | Описание | Вход | Выход |
| :--- | :--- | :--- | :--- |
| **`plot_2d_comparison`** | Строит графики $u(x)$ для нескольких выбранных моментов времени $T$ (сравнение схем и точного решения). | `all_data`, `all_times`, `figure` | `float`: `max_val_u` (для нормирования 3D-графиков) |
| **`plot_3d_evolution`** | Создает отдельную фигуру с $N$ (обычно 4) 3D-графиками для визуализации эволюции $u(x, t)$ (поверхности). | `all_data`, `all_times`, `max_val_u` | (None, отображает фигуру) |
| **`plot_error_graph`** | Строит график погрешности (нормы) $\lVert u_{\text{solved}} - u_{\text{true}} \rVert_{\max}(t)$. | `all_pogr`, `figure` | (None, настраивает subplot) |
| **`visualise_comparison`** | Главная функция-координатор для всего процесса. | `paths_dict` (dict): `{'Name': 'Path'}` | (None, отображает графики) |

### 3. ⚙️ Функциональные Требования

#### 3.1. Требования к Входным Данным
* **Организация файлов:** Каждая схема должна иметь свою папку.
* **Файлы решений:** Имена файлов должны быть в формате `*.txt`, содержать время $t$ на первой строке, а затем данные $(x, u_{\text{solved}}, u_{\text{true}})$ построчно. Имена файлов должны быть натурально сортируемыми (например, `0.01.txt`, `0.05.txt`, `1.0.txt`).
* **Файл погрешности:** Должен быть файл `p.txt` в той же папке, содержащий построчно $(t, \text{error\_norm})$.

#### 3.2. Требования к Графической Выходной Информации

1.  **Фигура 1 (2D Сравнение и Погрешность):**
    * **2D Сравнение:** Занимает верхнюю часть (3/4 высоты).
        * Должно отображаться **Точное Решение** (черной толстой линией с маркерами) и решения всех численных схем для **3 выбранных моментов времени** ($T/4, T/2, T_{\text{max}}$).
        * Каждому моменту времени должен соответствовать свой **цвет** (R, G, B).
        * Каждой схеме должен соответствовать свой **стиль линии** (сплошная, пунктирная, точечная).
        * Легенда должна четко указывать схему и время $t$.
    * **График Погрешности:** Занимает нижнюю часть (1/4 высоты).
        * Отображение $\lVert u_{\text{solved}} - u_{\text{true}} \rVert_{\max}$ как функции от времени $t$.
        * Каждая схема должна иметь свой цвет и стиль линии.

2.  **Фигура 2 (3D Эволюция):**
    * Отдельная фигура, содержащая $2 \times 2$ подграфика.
    * Отображение эволюции $u(x, t)$ в виде поверхности для **Точного Решения** (используя $u_{\text{true}}$ первой схемы) и трех численных схем (Явная, Неявная, Кранка-Николсона).
    * Оси $x, t, u$ должны быть четко подписаны.
    * Угол обзора: `elev=20`, `azim=-60`.
    * Должен присутствовать **colorbar**.
    * Ось $u$ (Z-axis) должна быть нормирована по максимальному значению, найденному в 2D-графике (`max_val_u`).

### 4. 🛠️ Технические Детали

* **Язык:** Python.
* **Библиотеки:** `os`, `matplotlib.pyplot`, `numpy`, `natsort`, `mpl_toolkits.mplot3d`.
* **Константы:** Стили линий и цветов для схем и погрешностей должны быть вынесены в глобальные словари (`SCHEME_STYLES`, `ERROR_STYLES`).
* **Обработка ошибок:** Должна быть предусмотрена обработка отсутствующих файлов `p.txt` или пустых папок.
